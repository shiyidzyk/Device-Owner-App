# tools 目录说明（PC 端配套）

| 文件 | 用途 |
|---|---|
| `pin_reset.py` | 重置核心：读私钥 → 对申请码里的挑战做 ECDSA-P256 签名 → 输出重置码（依赖 `pip install cryptography`） |
| `pin_reset.bat` | 双击版：自动找 Python、缺依赖自动安装，粘贴申请码即出重置码 |
| `pin_reset_gui.vbs` | 图形版：弹窗输入申请码、弹窗显示重置码；也支持 `cscript //nologo pin_reset_gui.vbs <申请码>`（结果走 stdout） |
| `wifilock_reset_private.key` | **重置私钥**，见下（脚本同时兼容 v2 新格式与 v1 旧格式） |

## wifilock_reset_private.key 是什么

这是 **App「应用锁（PIN）」的找回私钥**：应用锁的 PIN 忘记时，App 会显示一个一次性
申请码（`WFL1-<keyid>-<挑战>`），用私钥对它签名得到重置码（`WFR1-...`），回 App 验证
通过即删除 PIN——全程离线，无服务器。原理与安全设计见仓库根的《WifiLock 移交文档》§18。

**私钥格式（v1.5+ = v2）**：`WFLKEY2-<64 位 hex 私钥标量>`。
它由**设备标识（ANDROID_ID）确定性派生**——同一个设备上，无论反复开关应用锁、
重装应用、清除应用数据，App 重新生成的私钥**永远相同**；仅恢复出厂（ANDROID_ID
随系统重置）才会更换。好处：**私钥文件只需保存一次，长期有效**。

⚠️ **重置私钥不随仓库发布**：`WifiLock/tools/` 中的 key 文件仅存在于作者本地与备份
路径。它与设备绑定（设备标识确定性派生），含义是：**谁拿到私钥文件，谁就能为对应
设备生成重置码**——请妥善保管，不要放到手机存储里，不要提交到任何公开仓库。

## 怎么用（把私钥放进本目录）

1. 文件名保持 `wifilock_reset_private.key`，与本目录的脚本放在一起；
2. 双击 `pin_reset.bat` 或 `pin_reset_gui.vbs`，粘贴手机上「忘记 PIN」页的申请码；
3. 把输出的 `WFR1-...` 整行复制回 App 即可。

私钥不在本目录时也可以：`python pin_reset.py reset WFL1-xxxx-... --key "D:\备份\我的钥.key"`

## 怎么替换成你自己设备的私钥

1. 在**你的设备**上：App →「🔐 应用锁」→ 设置 PIN（v1.5+ 会显示
   `WFLKEY2-<64位hex>` 格式的私钥）；
2. 启用成功页会显示一串 **重置私钥（只显示这一次！）**——立即复制；
3. 新建纯文本文件，粘贴保存，改名为 `wifilock_reset_private.key`（内容就是那串
   `WFLKEY2-...`），放到本目录（替换示例钥）——**并立即停止跟踪/提交这个文件**
   （建议移到项目文件夹之外保存；由于密钥由设备派生，之后不会再生变化，保存一次即可）；
4. 多台设备 = 多把私钥。申请码 `WFL1-` 后的前 8 位是钥匙指纹；用 A 设备的钥给 B 设备
   的申请码签名会验签失败，脚本会提示"钥匙不一致"。

## 私钥对应关系速查

| 申请码样例 | 指纹段 | 说明 |
|---|---|---|
| `WFL1-461745b5-a896...` | `461745b5` | 必须与所用私钥文件的指纹一致（脚本会自动比对并告警） |
